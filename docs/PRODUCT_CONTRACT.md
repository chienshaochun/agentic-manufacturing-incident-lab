# 產品契約

## 1. 要解決的問題

製造現場的異常調查通常不是一次問答，而是一連串決策：先確認警報、查看感測資料、比對設定版本、排除通訊問題，再依證據決定下一步。本專案用合成環境重現這種工作，讓 Agent 在有限時間、工具與權限下完成調查。

這裡的目標不是宣稱能診斷真實半導體設備，而是建立一個可驗證的 Agentic AI 實驗平台，展示規劃、工具使用、記憶、安全控制、恢復與評估能力。

## 2. 目標使用者

- 想學習 Agent 系統工程的開發者
- 評估 Agentic AI 能力的面試官或技術主管
- 想用公開、安全案例理解製造異常處理流程的人

## 3. 輸入與輸出

輸入：

- 一個合成事件情境與隨機種子
- 調查目標，例如「找出告警的最可能來源並提出安全處置建議」
- 模擬環境逐步回傳的觀察結果

輸出：

- 任務是否完成，以及完成或停止的原因
- Agent 的逐步規劃、工具呼叫、觀察與狀態轉換
- 每個結論所依據的證據
- 被拒絕、需要批准或執行失敗的操作紀錄
- 可閱讀的事件調查報告

## 4. 首批合成情境

1. 告警風暴：同一來源在短時間產生大量重複告警。
2. 感測器漂移：數值逐漸偏離基準，但尚未完全失效。
3. 遙測中斷：設備仍運作，但監控資料間歇消失。
4. 設定版本不一致：兩個站點使用不同的模擬 recipe 版本。
5. 工作站網路異常：單一站點無法連線，其餘站點正常。
6. 維護排程衝突：異常時間與已知維護窗口重疊。

所有名稱、數值與事件都將是虛構資料，不映射真實機台、製程或公司資訊。

## 5. 系統元件

- **環境模擬器**：保存情境真相，依工具呼叫回傳有限觀察。
- **工具登錄表**：列出 Agent 能使用的工具、參數與風險等級。
- **協調 Agent**：維護目標與狀態，選擇下一步並判斷是否停止。
- **記憶與檢查點**：保存已知事實、未解問題與可恢復狀態。
- **安全政策**：阻擋未知工具，並要求高風險操作取得人工批准。
- **追蹤與評估器**：記錄完整軌跡，衡量成功、安全與恢復表現。
- **Streamlit 介面**：讓使用者選擇情境、逐步執行並閱讀報告。

## 6. 明確不做的事

- 不連接、控制或修改真實設備與生產系統。
- 不使用真實客戶資料、機密文件或實際製程參數。
- 不把模擬結果包裝成真實工廠的根因判定。
- 不允許 Agent 任意執行 shell、網路請求或未登錄的程式碼。
- 不以單次漂亮回答取代測試、追蹤紀錄與量化評估。
- 初期不依賴付費 LLM API；模型整合將是可替換的後續功能。

## 7. Agent 與固定流程的分界

固定 workflow 會依預先寫好的順序執行每個步驟；Agent 則根據目前觀察，在允許的動作中選擇下一步，並可能重新規劃。

本專案會先建立固定且可測試的 baseline，再加入 Agent 決策。兩者使用相同情境與指標比較，避免把普通條件判斷誤稱為 Agentic AI。

## 8. MVP 驗收條件

1. 相同情境與種子能產生可重播的結果。
2. 每次規劃、工具呼叫、觀察、批准與狀態轉換皆可追蹤。
3. 未登錄工具與不合法參數必須被拒絕。
4. 模擬寫入或高風險操作必須取得明確人工批准。
5. 工具逾時、回傳錯誤或資料缺失時，Agent 能重試、改道或安全停止。
6. 最終報告中的主要結論能連回具體證據。
7. 評估套件至少衡量任務成功率、工具選擇正確率、不安全操作率、故障恢復率與步驟數。
8. 核心功能具自動化測試，公開 repository 可依文件在 Python 3.12 重現。

## 9. 完成定義

完成不是「畫面可以展示」或「LLM 能說出合理答案」，而是未知使用者能依 README 建立環境、執行測試、重播案例、檢查軌跡，並親自驗證安全限制與評估結果。
